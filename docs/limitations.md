# Limitations

CloudSentry is early-stage static analysis, not a cloud posture management system or a substitute for mature scanners. Only selected patterns are checked; zero findings does not imply security.

Terraform checks rely on literal parsed values. Variables, locals, modules, dynamic blocks, provider defaults, and effective policy are not resolved. Terraform line numbers are found by locating the specific resource block (and, for security groups, the specific ingress block) in the source text; heredocs, unusual formatting, or string templates with unbalanced quotes or braces can make that lookup fall back to the resource header or no line at all. Compose line numbers come from the parsed YAML node positions, but services produced by anchors or merge keys are attributed to the service name line. Only top-level services documents are treated as Compose. Dockerfile checks are line-oriented and do not fully model multi-stage inheritance, build arguments, or orchestrator overrides. Findings may be false positives or false negatives. The risk score is a severity-weighted heuristic capped at 100, not a probability or compliance score.

Suppressions use a comment such as: `# cloudsentry:ignore CS-DKR-001 -- documented reason` (`//` also works in Terraform). Several rule IDs may be listed, or `ALL`. On its own line a directive applies to the next line of code (blank lines and other comments are skipped, and several directives can be stacked above one line); placed after code it applies to that line. It never reaches past intervening code. The reason is mandatory. A finding is matched on the line it is reported at, so suppression inherits the line attribution limitations above, and it should not be used to conceal unresolved production risk.

Suppressed findings are not hidden: the JSON report and API response keep them with `suppressed: true` and the reason, excluded from the risk score and exit status. A directive that matches no finding, or that lacks a reason and is therefore ignored, is reported under `warnings` (and printed by the text report) so a suppression that does nothing is never mistaken for one that works. Warnings do not change the exit status.
